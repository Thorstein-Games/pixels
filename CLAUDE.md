# CLAUDE.md

Pix Pen (formerly Pixels; a play on "pig pen"): ~100 pixels bounce around a grid; the player taps cells to place/remove blocks and wins once every pixel is sealed into at most `WIN_AREA_PERCENT` (15%) of the board's open cells. Placing a block on a pixel traps it (it shakes) until the block is removed, and you can't win while any pixel is trapped. Score = moves × seconds, lower is better. A daily board (seeded by local date) plus a practice mode (`#practice`).

Plain Vite + TypeScript, canvas rendering, no framework, no server. Built with `base: "/pix-pen/"` and deployed to GitHub Pages by `.github/workflows/deploy.yml` (the repo is still named `pixels`, so Pages serves it at `/pixels/`); thorstein-games-website proxies `thorsteingames.com/pix-pen` to it and 301s the old `/pixels` paths there. Internal names keep the old one on purpose: localStorage keys (`pixels.daily.*`, so streaks survived the rename), the daily seed prefix (`pixels:<date>`, changing it changes every daily board) and `window.__pixels`.

## Commands

```bash
npm run dev          # Vite dev server
npm run verify       # typecheck + unit tests — run before committing
npm run test:e2e -- --project=desktop --project=phone   # Playwright against a production build (~40s); CI also runs --project=iphone (WebKit)
npx vite-node scripts/balance.ts [seeds] ['{"roomMaxCells":14}']  # bot playtest: median time/moves to reach each area threshold
node scripts/logo.mjs && npx vite-node scripts/render-images.ts  # regenerate logo SVGs, then app icons + share image
```

## Tests

Deploys are gated: `deploy.yml` calls `ci.yml` and only publishes if it passes, so a red suite never ships; the site is built in a parallel job, so the deploy step only publishes. `ci.yml` runs unit tests and one Playwright job per project (desktop Chrome, Android Chrome, iPhone WebKit) in parallel inside the `mcr.microsoft.com/playwright` image, whose tag must match `@playwright/test` in package.json (a CI step checks). It also runs on every push to a branch other than main, so a branch can be checked before it reaches main, and uploads the Playwright report when a job fails.

- Unit (`tests/`, vitest): `determinism.test.ts` pins golden fingerprints of daily boards and 30s of pixie paths (if one fails after a tuning change, update the snapshot deliberately and note that today's board changes for players mid-way through it; otherwise find what broke determinism); `rules.test.ts` covers generation, bounces, trapping, the exact win threshold and a random-play fuzz checking no pixie ever leaves the area the win check counts; `progress.test.ts` covers localStorage (pre-rename keys, corrupt or unavailable storage), dates, streaks, merging two devices' saves, scoring and share text.
- E2E (`e2e/`, Playwright): `fixtures.ts` stubs the Thorstein Games bar and fails any test that logs a console error; import `test`/helpers from it in new specs. `critical.spec.ts` covers the daily across days (with `page.clock` and a pinned timezone), streaks, sharing, pause on help, trapped pixies blocking the win, pixies drawn on the canvas in both looks, layout at 320px to 1920px, and metadata/asset paths; `game.spec.ts` covers placing, aiming, restart, play again and score heat. The win card counts numbers up, so wait for final values (`toHaveText`) instead of reading them right away. The three-day streak test is skipped in WebKit only (it intermittently loses its page partway through in CI's WebKit); Chrome still runs it.

## Layout

- `src/game/config.ts` — every difficulty knob (grid size, pixel count/speed, spawn clusters, win ratio, room size). Tune here, and check changes with `scripts/balance.ts`: a bot tapping at human pace. Small rooms make doorways do the work; below ~15% the endgame turns into waiting for empty cells in crowded rooms, and time roughly triples. Changing generation or tuning changes that day's daily board for anyone who hasn't solved it yet.
- `src/game/level.ts` — `generateLevel(seed)`: recursive-division rooms with doorways, unreachable pockets sealed, pixels spawned in clusters. `floodFill` is shared with the sim.
- `src/game/sim.ts` — pure game state: fixed-timestep physics (`advance`/`step`, axis-separated bounces so pixels stay in 4-connected regions), `tap`, `measure` (reachable area; only changes on a tap, so the win check runs there).
- `src/daily.ts` — date keys, seed, streak math, localStorage (`pixels.daily.*`). Daily progress (clock + moves) survives reloads and restarts; the board itself resets.
- Cloud saves: signed-in players (Thorstein Games accounts, run by the hub's `tg-bar.js`; see its CLAUDE.md) get their stats and results on every device. `main.ts` registers `TG.sync({ game: "pix-pen", keys: SYNC_KEYS, merge: mergeSaves })` once `window.TG` exists and calls `cloud.save()` after a daily solve; when another device's progress arrives it re-runs `setupDaily()` unless a board is being played. `mergeSaves` (`daily.ts`, tested in `progress.test.ts`) unions solved days (better score per day) and recomputes the streak from them, so it is order-independent. Today's unfinished board (`pixels.daily.progress`) stays per device. If you add a key worth carrying across devices, add it to `SYNC_KEYS` and to `mergeSaves`.
- `src/main.ts` — DOM/UI wiring and the rAF loop; `src/render.ts` — canvas drawing and animations. Blocks are placed on pointer *up* (press shows an aim highlight, drag moves it, releasing off the board cancels); the canvas eats `touchstart` and the page uses `touch-action: manipulation` so iOS doesn't double-tap zoom. The board is sized by a `ResizeObserver` on `#board-wrap`, and `.app`'s max-width grows with screen height so tablets fill up.
- Shared Thorstein Games chrome: `index.html` loads `https://thorsteingames.com/tg-bar.js` (from the thorstein-games-website repo, whose CLAUDE.md has the full contract) and uses `<tg-bar game="pix-pen">` (thin site header, hides on scroll down), `<tg-footer game="pix-pen">` (after `.app`, so it starts below the fold) and `<tg-more-games game="pix-pen">` ("Play a different game", in the win card). The bar is always 40px: `style.css` holds that space before the script loads and `.app` is `100dvh - 40px`, so keep both in step if the board's height maths changes. The e2e spec stubs the script so tests don't depend on production.
- Ads (`<tg-ad>`, rules and options in the hub's CLAUDE.md): a `rail` beside `.app` on wide screens, a `box` under the win card (`#win-overlay` stacks card and ad and scrolls from the top, so neither is cut off) and a `banner` between `.app` and the footer. Never on the board or during play. Check placements with `?tgads=preview`.
- Branding: `scripts/logo.mjs` generates `public/favicon.svg` (the mark: amber blocks penning in winged pixies, one flying out trailing twinkles), `wordmark.svg` and `logo.svg` (header) from its `NAME` constant and a 5×7 pixel font; `scripts/render-images.ts` renders the PNG icons and `og-image.png` (a real board with pixies and sparkle trails, drawn by `render.ts`). Bump the `?v=` on the og:image URLs when the share image changes so link previews refetch it. thorstein-games-website's `public/pix-pen.svg` is a copy of the favicon for its homepage card.
- Pixies: the pixels are presented as pixies (player-facing text says "pixies"; code still says pixel). `render.ts` `drawPixies` gives each one a glow sprite, flapping wings and a trail of short-lived gold/pink sparkles (render-only state in `CellAnim.sparkles`; `Math.random` is fine there since it never touches the sim). `?look=classic` draws the original plain dots.
- `window.__pixels` exposes UI state so e2e tests can steer pixels instead of chasing them.

Determinism: the daily board and pixel paths must match on every device, so level generation avoids `Math.sin`/`cos` (only `sqrt`) and the sim always steps by `STEP_SECONDS`.
